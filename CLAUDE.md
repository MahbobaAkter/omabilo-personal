# Omabilo Personal: project instructions

A personal financial-wellbeing app built as an IKON C# app. Start each session by reading
`PROJECT_STATUS.md` (current state and next tasks). Read `DECISIONS.md` before changing the
architecture, storage, sign-in, Git remotes or deployment.

## Layout

- `app/Omabilo/`: the IKON app (server-rendered UI). There is one file per screen, plus `Models.cs` (shared types, `Fin` helpers, `DemoData`) and `Metrics.cs`.
- `app/Omabilo/Invoices/`: invoice collection.
  - `InvoiceModel.cs`, `InvoiceBook.cs`, `InvoiceSources.cs` and `SyntheticInvoices.cs` are **plain C# with no IKON types**. The tests and the backend compile them in directly; keep them that way.
  - `InvoiceService.cs` and `InvoicesScreen.cs` are the IKON glue and the screen.
- `test/Omabilo.Test/`: unit tests for the plain-C# invoice domain.
- `backend/`: a standalone ASP.NET Core API that runs without IKON (see `backend/README.md`). Finance and invoice maths live in `backend/src/Omabilo.Api/Finance` and the shared invoice files.
- `web/`: the standalone website (React + Vite + TypeScript) for Vercel. It talks only to `backend/` (see `web/README.md`, `DEPLOYMENT.md`).
- `frontend-node/`: the IKON thin client. It holds no app logic, only works against an IKON server, and must stay as it is or the IKON app breaks.
- `docs/`: IKON reference docs, regenerated by the `ikon` tool and git-ignored. Search them; never edit them.

## Commands (from the repo root)

```bash
ikon build
ikon run --detach
ikon browse --steps "observe"
dotnet test test/Omabilo.Test
dotnet test backend/Omabilo.Backend.slnx
npm --prefix web test
npm --prefix web run build
```

`ikon run --detach` hot-reloads `.cs` edits. A `dotnet build` of the app while it runs fails on a
locked `.exe`; build to another folder with `-o build/check-out` instead.

## Rules

- **Fictional data only.** Never connect real bank, mail or provider accounts, create live OAuth apps or ask for credentials. Simulated sources must stay labelled "Simulated".
- **A local `ikon run` reads and writes the deployed app's real state and database.** Test with synthetic data; the sidebar's "Reset demo data" and the Invoices screen's "Delete all invoice data" undo test activity.
- **Ask first** before committing, `ikon save`, `ikon deploy`, pushing to GitHub, or changing `ikon-config.toml` or production settings.
- **GitHub gets snapshot commits only** (see `DECISIONS.md`). Never push `main` to the `github` remote, and never force-push.
- Leave `frontend-node/package-lock.json` churn from `npm install` out of commits.
- Logs and audit events carry ids, counts and outcomes only: never amounts, references, document text or tokens.
